# Agent Instructions

Read and follow `CODEX.md` before working in this project.

`CODEX.md` is the compact operating guide for C/C++ documentation, including
repository layout, source policy, writing style, output naming, coverage gates,
and review expectations.

Read `LEARNING_PATH.md` before choosing or validating a learning-path number,
topic slug, canonical output path, or mapped source files.

For C/C++ learning, prefer the `$c-cpp` skill. The user may provide only a
topic, keyword, comparison, source hint, or interview request. Discover the
required C/C++ concepts from `MASTER_C_CPP_KNOWLEDGE_INDEX.md`, the expansion
rules from `C_CPP_CHAPTER_EXPANSION_GUIDE.md`, and the detailed C++ knowledge
from the mapped `docs/C++ Notion/` chapter files.

Never write a C++ topic without checking the mapped Notion files. Never claim a
topic is fully covered unless `coverage/topic-briefs/NN-<slug>.md` lists the
source files read and any external references used.

Keep this project focused on C/C++ language, standard library, memory, OOP, STL,
Modern C++, templates, error handling, concurrency, POSIX/Linux user-space API
comparisons, embedded C/C++ practice, enterprise code review, and interviews.
Do not mix in Linux Device Driver, kernel-driver, Yocto, GStreamer, AUTOSAR, or
unrelated platform material unless the user explicitly asks for it.

New finished outputs use learning-path naming such as
`knowledge/04-pointer-mastery.md`, `interview/04-pointer-mastery.md`, and
`examples/04-pointer-mastery/README.md`. Raw Notion chapter numbers are source
metadata only.
