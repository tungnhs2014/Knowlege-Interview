# Agent Instructions

Read and follow `CODEX.md` before working in this project.

`CODEX.md` is the compact operating guide for Linux Device Driver documentation,
including repository layout, writing style, coding expectations, interview answer
format, and context-window rules.

Read `LEARNING_PATH.md` when choosing or validating a learning-path number,
topic slug, or canonical output path.

For Linux Device Driver learning, prefer the `$linux-device-driver` skill. The
user may provide only Topic, Slug, optional learning-path number, and optional
Source. Discover important concepts from the source docs instead of asking the
user for kernel keywords.

New finished outputs use learning-path naming such as
`knowledge/07-character-device-drivers.md`,
`interview/07-character-device-drivers.md`, and
`examples/07-character-device-drivers/`. Raw source chapter numbers are source
metadata only.

Always treat the three source groups as independent:
- `ldd1`: `docs/Linux Device Driver Development/`
- `ldd2`: `docs/Linux Device Driver Development 2/`
- `notion`: `docs/Linux-Device-Driver-Notion/`

Same chapter numbers across source groups are not equivalent until read and
compared. Never skip Notion material as a duplicate without reading and mapping
it. Do not claim full coverage unless the topic or project coverage matrix backs
that claim.
