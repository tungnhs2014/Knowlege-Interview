# Part 1. I2C Architecture and Driver Structures

This part introduces the I2C protocol, Linux I2C subsystem architecture, and the fundamental data structures used in I2C client driver development.

---

## 7.1 I2C Protocol Fundamentals

### 7.1.1 What is I2C?

**I2C** (Inter-Integrated Circuit), invented by Philips (now NXP), is a **two-wire serial bus** used for communication between integrated circuits.

**Bus signals:**

```
┌──────────────────────────────────────────────────┐
│  I2C Bus - Two Wire Communication                │
├──────────────────────────────────────────────────┤
│                                                  │
│  SDA (Serial Data)   ─────────────────────       │
│                      Bidirectional data line     │
│                                                  │
│  SCL (Serial Clock)  ─────────────────────       │
│                      Clock generated by master   │
│                                                  │
│  Both lines require PULL-UP resistors            │
│  (Open-drain/Open-collector configuration)       │
└──────────────────────────────────────────────────┘
```

**Key characteristics:**

- **Two-wire bus**: SDA (Serial Data) and SCL (Serial Clock)
- **Multi-master capable**: Though multi-master mode is rarely used
- **Open drain/Open collector**: Lines can drive low, but need pull-ups for high
- **Master-slave architecture**: Master generates clock and initiates transactions
- **Addressable**: Each slave has a unique 7-bit or 10-bit address

### 7.1.2 I2C Bus Topology

**Typical I2C system:**

```
        Pull-up Resistors
         Vcc    Vcc
          │      │
          ▼      ▼
         ┌┴┐    ┌┴┐
         └┬┘    └┬┘
    ┌─────┴──────┴─────────────────────┐
    │     SDA    SCL                    │
    │                                   │
┌───┴────┐         ┌──────────┐   ┌──────────┐
│ Master │─────────│ Slave 1  │───│ Slave 2  │
│ (SoC)  │         │ (EEPROM) │   │  (RTC)   │
└────────┘         │ Addr:0x50│   │Addr:0x68 │
                   └──────────┘   └──────────┘
```

**Common I2C devices:**

- Serial EEPROM (memory)
- RTC (Real-Time Clock) chips
- GPIO expanders
- Temperature sensors
- Audio codecs
- Power management ICs (PMICs)

### 7.1.3 I2C Specifications

**Clock speeds:**

```
┌────────────────────────────────────────────────┐
│  I2C Speed Modes                               │
├────────────────────────────────────────────────┤
│  Standard Mode      100 kHz                    │
│  Fast Mode          400 kHz                    │
│  Fast Mode Plus     1 MHz                      │
│  High Speed Mode    3.4 MHz                    │
│  Ultra Fast Mode    5 MHz                      │
└────────────────────────────────────────────────┘
```

**Important notes:**

- Master always generates the clock (SCL)
- Master always initiates communication
- Slave can stretch the clock by holding SCL low
- Both SDA and SCL are bidirectional

**For complete I2C specifications:**

- NXP I2C Specification: http://www.nxp.com/documents/user_manual/UM10204.pdf

### 7.1.4 I2C Transaction Format

**Basic read/write transaction:**

```
START condition
│
▼
┌─────────────┬───┬──────────────┬───┬──────────┬───┬──────┐
│ Slave Addr  │R/W│   ACK/NACK   │   │   Data   │ACK│ STOP │
│  (7 bits)   │(1)│              │   │ (8 bits) │   │      │
└─────────────┴───┴──────────────┴───┴──────────┴───┴──────┘
     ▲         ▲         ▲                  ▲         ▲
  Master    Master    Slave            Master/     Master
  sends     sends    responds          Slave      generates
                                       exchange
```

**R/W bit:**

- `0` = Write operation
- `1` = Read operation

## 7.2 Linux I2C Subsystem Architecture

### 7.2.1 I2C Subsystem Overview

The Linux I2C subsystem consists of three main components:

```
┌────────────────────────────────────────────────┐
│         Linux I2C Subsystem Architecture       │
├────────────────────────────────────────────────┤
│                                                │
│  ┌──────────────────────────────────────────┐  │
│  │      I2C Core (drivers/i2c/i2c-core.c)   │  │
│  │  - Device/driver matching                │  │
│  │  - Bus management                        │  │
│  │  - API implementation                    │  │
│  └──────────────────────────────────────────┘  │
│            ▲                    ▲              │
│            │                    │              │
│  ┌─────────┴─────────┐  ┌──────┴──────────┐    │
│  │ I2C Algorithm     │  │ I2C Client      │    │
│  │ (Bus Driver)      │  │ (Device Driver) │    │
│  │                   │  │                 │    │
│  │ - imx-i2c.c       │  │ - Your driver   │    │
│  │ - i2c-gpio.c      │  │ - eeprom.c      │    │
│  │ - Bit-banging     │  │ - rtc-ds1307.c  │    │
│  └───────────────────┘  └─────────────────┘    │
│            │                    │              │
│            ▼                    ▼              │
│  ┌──────────────────────────────────────────┐  │
│  │      Hardware I2C Controller             │  │
│  │      (Physical bus controller)           │  │
│  └──────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
```

**Component responsibilities:**

1. **I2C Core** (`drivers/i2c/i2c-core.c`)
    - Device/driver registration and matching
    - Bus abstraction
    - API implementation (transfer functions)
    - Sysfs interface
2. **I2C Algorithm/Bus Driver** (`drivers/i2c/busses/`)
    - Controls the physical I2C controller (SoC peripheral)
    - Implements low-level bus operations
    - Handles hardware-specific details
    - Example: `i2c-imx.c` for i.MX6 SoC
3. **I2C Client Driver** (What we write!)
    - Drives specific I2C slave devices
    - Uses I2C core APIs for communication
    - Independent of bus controller hardware
    - Example: EEPROM driver, RTC driver

### 7.2.2 Abstraction Benefits

**Why this architecture matters:**

```
┌─────────────────────────────────────────────────┐
│  Your I2C Client Driver                         │
│  (Device-specific logic)                        │
└──────────────┬──────────────────────────────────┘
               │ Uses I2C Core API
               │ (i2c_master_send, i2c_transfer)
               ▼
┌─────────────────────────────────────────────────┐
│  I2C Core                                       │
│  (Bus-agnostic transaction handling)            │
└──────────────┬──────────────────────────────────┘
               │ Calls algorithm-specific ops
               ▼
┌─────────────────────────────────────────────────┐
│  I2C Bus Driver (Algorithm)                     │
│  (Hardware-specific implementation)             │
│  - i.MX6 → i2c-imx.c                            │
│  - Rockchip → i2c-rk3x.c                        │
│  - GPIO bit-bang → i2c-gpio.c                   │
└─────────────────────────────────────────────────┘
```

**Key advantage:** Your client driver works with **any** I2C bus controller!

## 7.3 I2C Driver Structure - struct i2c_driver

### 7.3.1 The i2c_driver Structure

An I2C driver is represented in the kernel as an instance of `struct i2c_driver`:

```c
struct i2c_driver {
    /* Standard driver model interfaces */
    int (*probe)(struct i2c_client *, const struct i2c_device_id *);
    int (*remove)(struct i2c_client *);

    /* Driver model interfaces */
    void (*shutdown)(struct i2c_client *);

    /* Device driver structure */
    struct device_driver driver;

    /* Device ID table for matching */
    const struct i2c_device_id *id_table;

    /* Additional fields... */
};
```

**Field descriptions:**

- `probe`: Called when device is detected/matched
- `remove`: Called when device is removed
- `shutdown`: Called during system shutdown
- `driver`: Generic driver structure (contains OF match table)
- `id_table`: Array of device IDs this driver supports

### 7.3.2 Complete Example - Basic Driver Declaration

```c
#include <linux/module.h>
#include <linux/i2c.h>

/* Device ID table */
static const struct i2c_device_id my_i2c_id[] = {
    { "my-i2c-device", 0 },
    { "my-i2c-sensor", 1 },
    { }  /* Sentinel */
};
MODULE_DEVICE_TABLE(i2c, my_i2c_id);

/* OF match table (Device Tree) */
static const struct of_device_id my_i2c_of_match[] = {
    { .compatible = "vendor,my-i2c-device", },
    { .compatible = "vendor,my-i2c-sensor", },
    { }  /* Sentinel */
};
MODULE_DEVICE_TABLE(of, my_i2c_of_match);

/* Probe function */
static int my_i2c_probe(struct i2c_client *client,
                       const struct i2c_device_id *id)
{
    dev_info(&client->dev, "Device probed: %s at address 0x%02x\n",
             client->name, client->addr);

    /* Device initialization goes here */

    return 0;
}

/* Remove function */
static int my_i2c_remove(struct i2c_client *client)
{
    dev_info(&client->dev, "Device removed\n");

    /* Cleanup goes here */

    return 0;
}

/* I2C driver structure */
static struct i2c_driver my_i2c_driver = {
    .driver = {
        .name = "my-i2c-driver",
        .of_match_table = my_i2c_of_match,
    },
    .probe = my_i2c_probe,
    .remove = my_i2c_remove,
    .id_table = my_i2c_id,
};

/* Register driver */
module_i2c_driver(my_i2c_driver);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Your Name");
MODULE_DESCRIPTION("Example I2C Driver");
```

### 7.3.3 Driver Registration

**Old way (manual registration):**

```c
static int __init my_i2c_init(void)
{
    return i2c_add_driver(&my_i2c_driver);
}

static void __exit my_i2c_exit(void)
{
    i2c_del_driver(&my_i2c_driver);
}

module_init(my_i2c_init);
module_exit(my_i2c_exit);
```

**New way (recommended):**

```c
module_i2c_driver(my_i2c_driver);
```

The `module_i2c_driver()` macro automatically generates init/exit functions!

## 7.4 I2C Client Structure - struct i2c_client

### 7.4.1 The i2c_client Structure

The `struct i2c_client` represents an **I2C slave device**:

```c
struct i2c_client {
    unsigned short flags;        /* Device flags */
    unsigned short addr;         /* 7-bit chip address (0x00-0x7F) */

    char name[I2C_NAME_SIZE];    /* Device name */

    struct i2c_adapter *adapter; /* I2C bus adapter we sit on */
    struct device dev;           /* Device structure */

    int irq;                     /* IRQ issued by device */

    struct list_head detected;

#if IS_ENABLED(CONFIG_I2C_SLAVE)
    i2c_slave_cb_t slave_cb;     /* Callback for slave mode */
#endif
};
```

**Key fields:**

```
┌──────────────────────────────────────────────────┐
│  struct i2c_client                               │
├──────────────────────────────────────────────────┤
│                                                  │
│  addr = 0x50        ← Device I2C address         │
│  name = "eeprom"    ← Device name                │
│  adapter = &i2c0    ← Which I2C bus              │
│  dev = { ... }      ← Generic device struct      │
│  irq = 56           ← Interrupt number           │
│                                                  │
└──────────────────────────────────────────────────┘
```

**Important notes:**

- All fields are filled by the kernel based on Device Tree or board files
- `addr` is 7-bit address (stored in lower 7 bits)
- `adapter` points to the I2C bus controller (bus driver)
- `dev` embeds generic device structure (for device model)

### 7.4.2 Accessing i2c_client in Driver

**In probe function:**

```c
static int my_probe(struct i2c_client *client,
                   const struct i2c_device_id *id)
{
    /* Client is provided by kernel */
    dev_info(&client->dev, "Device name: %s\n", client->name);
    dev_info(&client->dev, "I2C address: 0x%02x\n", client->addr);
    dev_info(&client->dev, "IRQ number: %d\n", client->irq);

    /* Check adapter functionality */
    if (!i2c_check_functionality(client->adapter,
                                I2C_FUNC_SMBUS_BYTE_DATA)) {
        dev_err(&client->dev, "Adapter doesn't support SMBus\n");
        return -EIO;
    }

    return 0;
}
```

### 7.4.3 Relationship: i2c_driver vs i2c_client

**Visual representation:**

```
┌────────────────────────────────────────────────┐
│                                                │
│  struct i2c_driver                             │
│  ┌──────────────────────────────────────────┐  │
│  │ - probe()                                │  │
│  │ - remove()                               │  │
│  │ - id_table                               │  │
│  │ - of_match_table                         │  │
│  └──────────────────────────────────────────┘  │
│         │                                      │
│         │ Manages                              │
│         ▼                                      │
│  struct i2c_client (Device Instance)           │
│  ┌──────────────────────────────────────────┐  │
│  │ - addr = 0x50                            │  │
│  │ - name = "eeprom"                        │  │
│  │ - adapter = &i2c0                        │  │
│  │ - irq = 56                               │  │
│  └──────────────────────────────────────────┘  │
│                                                │
│  Driver (code) ←→ Client (hardware instance)   │
└────────────────────────────────────────────────┘
```

**Analogy:**

- `i2c_driver` = Class (driver code)
- `i2c_client` = Object (device instance)

One driver can manage multiple client devices!

## 7.5 The Probe Function

### 7.5.1 Probe Function Responsibilities

The **probe function** is called when:

- Device is registered with I2C core
- Driver is loaded and matches a device
- Device Tree node is instantiated

**Prototype:**

```c
static int my_probe(struct i2c_client *client,
                   const struct i2c_device_id *id);
```

**Parameters:**

- `client`: Pointer to I2C client structure (device info)
- `id`: Pointer to matching ID table entry

### 7.5.2 Probe Function Tasks

**What the probe function should do:**

```c
static int my_probe(struct i2c_client *client,
                   const struct i2c_device_id *id)
{
    struct my_device_data *data;
    int ret;

    /* 1. Verify adapter functionality */
    if (!i2c_check_functionality(client->adapter,
                                I2C_FUNC_SMBUS_BYTE_DATA)) {
        dev_err(&client->dev, "Adapter doesn't support required ops\n");
        return -ENODEV;
    }

    /* 2. Allocate private data structure */
    data = devm_kzalloc(&client->dev, sizeof(*data), GFP_KERNEL);
    if (!data)
        return -ENOMEM;

    /* 3. Initialize private data */
    data->client = client;
    mutex_init(&data->lock);

    /* 4. Store private data in client */
    i2c_set_clientdata(client, data);

    /* 5. Verify device is present (optional) */
    ret = i2c_smbus_read_byte_data(client, DEVICE_ID_REG);
    if (ret < 0) {
        dev_err(&client->dev, "Failed to communicate with device\n");
        return ret;
    }

    /* 6. Check device ID */
    if (ret != EXPECTED_DEVICE_ID) {
        dev_err(&client->dev, "Unexpected device ID: 0x%02x\n", ret);
        return -ENODEV;
    }

    /* 7. Configure device */
    ret = my_device_configure(client);
    if (ret < 0)
        return ret;

    /* 8. Register with kernel framework */
    /* (GPIO subsystem, IIO, input, etc.) */
    ret = my_device_register(data);
    if (ret < 0) {
        dev_err(&client->dev, "Failed to register device\n");
        return ret;
    }

    dev_info(&client->dev, "Device probed successfully\n");
    return 0;
}
```

### 7.5.3 Checking Adapter Functionality

**API:**

```c
int i2c_check_functionality(struct i2c_adapter *adap, u32 func);
```

**Common functionality flags:**

```c
/* Plain I2C operations */
I2C_FUNC_I2C                    /* Plain I2C transactions */

/* SMBus operations */
I2C_FUNC_SMBUS_QUICK            /* SMBus Quick command */
I2C_FUNC_SMBUS_BYTE             /* SMBus byte read/write */
I2C_FUNC_SMBUS_BYTE_DATA        /* SMBus byte data read/write */
I2C_FUNC_SMBUS_WORD_DATA        /* SMBus word data read/write */
I2C_FUNC_SMBUS_BLOCK_DATA       /* SMBus block data read/write */

/* Combined flags */
I2C_FUNC_SMBUS_EMUL             /* All SMBus emulated */
```

**Example usage:**

```c
/* Check for multiple functionalities */
if (!i2c_check_functionality(client->adapter,
                            I2C_FUNC_SMBUS_BYTE_DATA |
                            I2C_FUNC_SMBUS_WORD_DATA)) {
    dev_err(&client->dev, "Required SMBus ops not supported\n");
    return -EIO;
}
```

## 7.6 Per-Device Data Management

### 7.6.1 Why Per-Device Data?

Each device instance needs its own private data:

```
┌─────────────────────────────────────────────┐
│  Multiple Device Instances                  │
├─────────────────────────────────────────────┤
│                                             │
│  EEPROM @0x50    EEPROM @0x51               │
│  ┌──────────┐   ┌──────────┐                │
│  │ Private  │   │ Private  │                │
│  │ Data     │   │ Data     │                │
│  │ - buffer │   │ - buffer │                │
│  │ - mutex  │   │ - mutex  │                │
│  │ - client │   │ - client │                │
│  └──────────┘   └──────────┘                │
│       ▲              ▲                      │
│       │              │                      │
│       └──────┬───────┘                      │
│              │                              │
│         Same Driver                         │
└─────────────────────────────────────────────┘
```

### 7.6.2 Storing and Retrieving Per-Device Data

**APIs:**

```c
/* Set client data */
void i2c_set_clientdata(struct i2c_client *client, void *data);

/* Get client data */
void *i2c_get_clientdata(const struct i2c_client *client);
```

**Complete example:**

```c
/* Device-specific data structure */
struct my_device {
    struct i2c_client *client;
    struct mutex lock;
    u8 buffer[256];
    int current_state;
};

static int my_probe(struct i2c_client *client,
                   const struct i2c_device_id *id)
{
    struct my_device *dev;

    /* Allocate private data */
    dev = devm_kzalloc(&client->dev, sizeof(*dev), GFP_KERNEL);
    if (!dev)
        return -ENOMEM;

    /* Initialize private data */
    dev->client = client;
    mutex_init(&dev->lock);
    dev->current_state = 0;

    /* Store private data */
    i2c_set_clientdata(client, dev);

    /* Now we can retrieve it anytime */
    return 0;
}

static int my_remove(struct i2c_client *client)
{
    struct my_device *dev;

    /* Retrieve private data */
    dev = i2c_get_clientdata(client);

    /* Cleanup */
    mutex_destroy(&dev->lock);

    return 0;
}
```

### 7.6.3 Real-World Example: GPIO Expander

**From `drivers/gpio/gpio-mc9s08dz60.c`:**

```c
/* Device-specific data structure */
struct mc9s08dz60 {
    struct i2c_client *client;
    struct gpio_chip chip;
};

static int mc9s08dz60_probe(struct i2c_client *client,
                           const struct i2c_device_id *id)
{
    struct mc9s08dz60 *mc9s;

    /* Check adapter functionality */
    if (!i2c_check_functionality(client->adapter,
                                I2C_FUNC_SMBUS_BYTE_DATA))
        return -EIO;

    /* Allocate device-specific data */
    mc9s = devm_kzalloc(&client->dev, sizeof(*mc9s), GFP_KERNEL);
    if (!mc9s)
        return -ENOMEM;

    /* Initialize private data */
    mc9s->client = client;

    /* Set up GPIO chip structure */
    mc9s->chip.label = client->name;
    mc9s->chip.base = -1;  /* Dynamic allocation */
    mc9s->chip.dev = &client->dev;
    mc9s->chip.owner = THIS_MODULE;
    mc9s->chip.ngpio = 16;  /* 16 GPIO lines */
    mc9s->chip.can_sleep = 1;  /* I2C ops can sleep */
    mc9s->chip.get = mc9s08dz60_get_value;
    mc9s->chip.set = mc9s08dz60_set_value;
    mc9s->chip.direction_output = mc9s08dz60_direction_output;
    mc9s->chip.direction_input = mc9s08dz60_direction_input;

    /* Store private data in client */
    i2c_set_clientdata(client, mc9s);

    /* Register GPIO chip */
    return gpiochip_add(&mc9s->chip);
}

static int mc9s08dz60_remove(struct i2c_client *client)
{
    struct mc9s08dz60 *mc9s;

    /* Retrieve our private data */
    mc9s = i2c_get_clientdata(client);

    /* Unregister GPIO chip */
    return gpiochip_remove(&mc9s->chip);
}
```

**Key points:**

- Private data stores both I2C client and GPIO chip
- `devm_kzalloc` for automatic memory cleanup
- `i2c_set_clientdata` / `i2c_get_clientdata` for data management

## 7.7 The Remove Function

### 7.7.1 Remove Function Responsibilities

**Prototype:**

```c
static int my_remove(struct i2c_client *client);
```

**What the remove function should do:**

```c
static int my_remove(struct i2c_client *client)
{
    struct my_device *dev = i2c_get_clientdata(client);

    /* 1. Unregister from kernel framework */
    my_device_unregister(dev);

    /* 2. Free IRQ if allocated */
    if (dev->irq_allocated)
        devm_free_irq(&client->dev, client->irq, dev);

    /* 3. Destroy synchronization primitives */
    mutex_destroy(&dev->lock);

    /* 4. Free any allocated buffers (if not using devm_*) */
    /* kfree() not needed if allocated with devm_kzalloc() */

    dev_info(&client->dev, "Device removed\n");

    return 0;
}
```

**Important:** Remove function must **undo everything** done in probe!

### 7.7.2 Complete Driver Template

```c
#include <linux/module.h>
#include <linux/i2c.h>
#include <linux/of.h>

/* Private data structure */
struct my_device {
    struct i2c_client *client;
    struct mutex lock;
    /* Add your fields here */
};

/* Device ID table */
static const struct i2c_device_id my_id[] = {
    { "my-device", 0 },
    { }
};
MODULE_DEVICE_TABLE(i2c, my_id);

/* OF match table */
static const struct of_device_id my_of_match[] = {
    { .compatible = "vendor,my-device", },
    { }
};
MODULE_DEVICE_TABLE(of, my_of_match);

/* Probe function */
static int my_probe(struct i2c_client *client,
                   const struct i2c_device_id *id)
{
    struct my_device *dev;
    int ret;

    /* Check functionality */
    if (!i2c_check_functionality(client->adapter,
                                I2C_FUNC_SMBUS_BYTE_DATA))
        return -EIO;

    /* Allocate private data */
    dev = devm_kzalloc(&client->dev, sizeof(*dev), GFP_KERNEL);
    if (!dev)
        return -ENOMEM;

    /* Initialize */
    dev->client = client;
    mutex_init(&dev->lock);

    /* Store private data */
    i2c_set_clientdata(client, dev);

    /* Device-specific initialization */
    ret = /* your init code */;
    if (ret < 0)
        return ret;

    dev_info(&client->dev, "Probe successful\n");
    return 0;
}

/* Remove function */
static int my_remove(struct i2c_client *client)
{
    struct my_device *dev = i2c_get_clientdata(client);

    /* Cleanup */
    mutex_destroy(&dev->lock);

    dev_info(&client->dev, "Device removed\n");
    return 0;
}

/* I2C driver structure */
static struct i2c_driver my_driver = {
    .driver = {
        .name = "my-driver",
        .of_match_table = my_of_match,
    },
    .probe = my_probe,
    .remove = my_remove,
    .id_table = my_id,
};

module_i2c_driver(my_driver);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Your Name");
MODULE_DESCRIPTION("I2C Driver Template");
```
