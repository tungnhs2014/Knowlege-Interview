# Part 1. SPI Architecture and Driver Structures

This part introduces the SPI protocol, Linux SPI subsystem architecture, and fundamental data structures used in SPI device driver development.

---

## 8.1 SPI Protocol Fundamentals

### 8.1.1 What is SPI?

**SPI** (Serial Peripheral Interface) is a **four-wire synchronous serial bus** used for high-speed communication between microcontrollers and peripheral devices.

**Bus signals:**

```
┌──────────────────────────────────────────────────┐
│  SPI Bus - Four Wire Communication               │
├──────────────────────────────────────────────────┤
│                                                  │
│  MOSI (Master Out Slave In)  ─────────────►      │
│       Data from master to slave                  │
│                                                  │
│  MISO (Master In Slave Out)  ◄─────────────      │
│       Data from slave to master                  │
│                                                  │
│  SCK  (Serial Clock)         ─────────────►      │
│       Clock generated by master                  │
│                                                  │
│  CS   (Chip Select)          ─────────────►      │
│       Slave selection (active low)               │
│                                                  │
│  Full-duplex: MOSI and MISO active simultaneously│
└──────────────────────────────────────────────────┘
```

**Key characteristics:**

- **Four-wire bus**: MOSI, MISO, SCK, CS
- **Master-slave only**: Master always controls the bus
- **Full-duplex**: Simultaneous bidirectional data transfer
- **High speed**: Up to 80+ MHz (much faster than I2C)
- **Simple protocol**: No acknowledgment, no addressing overhead

### 8.1.2 Signal Name Synonyms

**Different manufacturers use different names:**

```
┌────────────────────────────────────────────────┐
│  SPI Signal Name Variations                    │
├────────────────────────────────────────────────┤
│                                                │
│  MOSI (Master Out Slave In)                    │
│    Also called: SIMO, SDI, DI, SDA             │
│                                                │
│  MISO (Master In Slave Out)                    │
│    Also called: SOMI, SDO, DO, SDA             │
│                                                │
│  SCK (Serial Clock)                            │
│    Also called: CLK, SCL                       │
│                                                │
│  CS (Chip Select)                              │
│    Also called: SS̅, CSx, EN, ENB               │
│    Usually active LOW signal                   │
│                                                │
└────────────────────────────────────────────────┘
```

### 8.1.3 SPI Bus Topology

**Typical SPI system with multiple slaves:**

```
                    VCC
                     │
                     ▼
                    ┌┴┐ Pull-up (optional)
                    └┬┘
    ┌────────────────┴────────────────────────┐
    │         MOSI   MISO   SCK                │
    │           │      │      │                │
┌───┴────┐      │      │      │                │
│ Master │──────┴──────┴──────┴────────┐      │
│ (SoC)  │                              │      │
│        │── CS0 ────┐                  │      │
│        │── CS1 ───┐│                  │      │
│        │── CS2 ──┐││                  │      │
└────────┘         │││                  │      │
                   │││                  │      │
              ┌────┴┴┴──────────────────┴───┐  │
              │  Shared: MOSI, MISO, SCK    │  │
              └─────────────────────────────┘  │
                   │    │    │                 │
             ┌─────┴─┐ ┌┴────┴──┐  ┌──────────┴┐
             │Slave 0│ │Slave 1 │  │  Slave 2  │
             │ Flash │ │  ADC   │  │    DAC    │
             │ CS=0  │ │ CS=1   │  │   CS=2    │
             └───────┘ └────────┘  └───────────┘
```

**Important notes:**

- Master generates SCK clock
- Master controls CS lines (one per slave)
- MOSI, MISO, SCK are shared among all slaves
- Only one CS active at a time
- CS is usually active-low (0 = selected)

## 8.2 Linux SPI Subsystem Architecture

### 8.2.1 SPI Subsystem Overview

**The Linux SPI subsystem consists of three layers:**

```
┌────────────────────────────────────────────────┐
│       Linux SPI Subsystem Architecture         │
├────────────────────────────────────────────────┤
│                                                │
│  ┌──────────────────────────────────────────┐  │
│  │    SPI Core (drivers/spi/spi.c)          │  │
│  │  - Device/driver matching                │  │
│  │  - Message queue management              │  │
│  │  - API implementation                    │  │
│  └──────────────────────────────────────────┘  │
│            ▲                   ▲               │
│            │                   │               │
│  ┌─────────┴─────────┐  ┌──────┴──────────┐    │
│  │ SPI Controller    │  │ SPI Device      │    │
│  │ (Master Driver)   │  │ (Client Driver) │    │
│  │                   │  │                 │    │
│  │ - spi-imx.c       │  │ - Your driver   │    │
│  │ - spi-bcm2835.c   │  │ - spidev.c      │    │
│  │ - Bit-banging     │  │ - m25p80.c      │    │
│  └───────────────────┘  └─────────────────┘    │  
│            │                    │              │
│            ▼                    ▼              │
│  ┌──────────────────────────────────────────┐  │
│  │    Hardware SPI Controller               │  │
│  │    (Physical master controller)          │  │  
│  └──────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
```

**Component responsibilities:**

1. **SPI Core** (`drivers/spi/spi.c`)
    - Device/driver registration and matching
    - Message queue management
    - Transfer scheduling
    - Sysfs interface
2. **SPI Controller Driver** (`drivers/spi/spi-*.c`)
    - Controls physical SPI master hardware
    - Implements low-level transfer operations
    - Manages CS lines, clock, DMA
    - Example: `spi-imx.c` for i.MX6 SoC
3. **SPI Device Driver** (What we write!)
    - Drives specific SPI slave devices
    - Uses SPI core APIs for communication
    - Independent of controller hardware
    - Example: Flash driver, ADC driver

### 8.2.2 Required Header File

**All SPI drivers must include:**

```c
#include <linux/spi/spi.h>
```

This header provides:

- `struct spi_device`
- `struct spi_driver`
- `struct spi_transfer`
- `struct spi_message`
- All SPI API functions

## 8.3 SPI Device Structure - struct spi_device

### 8.3.1 The spi_device Structure

**Definition from `include/linux/spi/spi.h`:**

```c
struct spi_device {
    struct device dev;              /* Generic device structure */
    struct spi_master *master;      /* SPI controller */

    u32 max_speed_hz;               /* Maximum clock speed */
    u8 chip_select;                 /* Chip select index */
    u8 bits_per_word;               /* Bits per word */
    u16 mode;                       /* SPI mode (CPOL, CPHA) */

    int irq;                        /* IRQ number */
    int cs_gpio;                    /* Chip select GPIO */

    /* Additional fields... */
};
```

**Field descriptions:**

```
┌──────────────────────────────────────────────────┐
│  struct spi_device                               │
├──────────────────────────────────────────────────┤
│                                                  │
│  dev              ← Generic device structure     │
│  master           ← SPI controller this sits on  │
│  max_speed_hz     ← Max SCK frequency (Hz)       │
│  chip_select      ← CS index (0, 1, 2...)        │
│  bits_per_word    ← Word size (8, 16, 32 bits)   │
│  mode             ← SPI mode (0, 1, 2, 3)        │
│  irq              ← Interrupt number             │
│  cs_gpio          ← GPIO for chip select         │
│                                                  │
└──────────────────────────────────────────────────┘
```

### 8.3.2 Field Details

**master:**

- Points to the SPI controller (bus) managing this device
- Represents the physical SPI master hardware

**max_speed_hz:**

- Maximum SCK clock frequency in Hz
- Can be overridden per-transfer
- Example: `20000000` = 20 MHz

**chip_select:**

- Index in the CS GPIO list (starts from 0)
- Used to select which slave to communicate with
- Default: active low (can be inverted with `SPI_CS_HIGH`)

**bits_per_word:**

- Size of data word in bits (typically 8, 16, or 32)
- Can be overridden per-transfer
- Default: 8 bits

**mode:**

- Defines clock polarity (CPOL) and phase (CPHA)
- Values: `SPI_MODE_0`, `SPI_MODE_1`, `SPI_MODE_2`, `SPI_MODE_3`
- Can include additional flags like `SPI_LSB_FIRST`, `SPI_CS_HIGH`

**irq:**

- Interrupt number for this device
- Used with `request_irq()` if device generates interrupts

## 8.4 SPI Modes - CPOL and CPHA

### 8.4.1 Understanding SPI Modes

**SPI modes are built from two characteristics:**

```
┌────────────────────────────────────────────────┐
│  CPOL (Clock Polarity)                         │
├────────────────────────────────────────────────┤
│  0 = Clock idle state is LOW                   │
│      First edge is RISING                      │
│                                                │
│  1 = Clock idle state is HIGH                  │
│      First edge is FALLING                     │
└────────────────────────────────────────────────┘

┌────────────────────────────────────────────────┐
│  CPHA (Clock Phase)                            │
├────────────────────────────────────────────────┤
│  0 = Data sampled on FIRST clock edge          │
│      Data changed on SECOND edge               │
│                                                │
│  1 = Data sampled on SECOND clock edge         │
│      Data changed on FIRST edge                │
└────────────────────────────────────────────────┘
```

### 8.4.2 Four SPI Modes

**Kernel macros from `include/linux/spi/spi.h`:**

```c
#define SPI_CPHA    0x01    /* Clock phase */
#define SPI_CPOL    0x02    /* Clock polarity */

/* Combined modes */
#define SPI_MODE_0  (0|0)           /* CPOL=0, CPHA=0 */
#define SPI_MODE_1  (0|SPI_CPHA)    /* CPOL=0, CPHA=1 */
#define SPI_MODE_2  (SPI_CPOL|0)    /* CPOL=1, CPHA=0 */
#define SPI_MODE_3  (SPI_CPOL|SPI_CPHA)  /* CPOL=1, CPHA=1 */
```

**Summary table:**

```
┌──────┬──────┬──────┬─────────────────────────┐
│ Mode │ CPOL │ CPHA │ Kernel Macro            │
├──────┼──────┼──────┼─────────────────────────┤
│  0   │  0   │  0   │ SPI_MODE_0 (0|0)        │
│  1   │  0   │  1   │ SPI_MODE_1 (0|SPI_CPHA) │
│  2   │  1   │  0   │ SPI_MODE_2 (SPI_CPOL|0) │
│  3   │  1   │  1   │ SPI_MODE_3 (both set)   │
└──────┴──────┴──────┴─────────────────────────┘
```

### 8.4.3 Visual Representation of SPI Modes

**Mode 0 (CPOL=0, CPHA=0):**

```
SCK  ──┐   ┌───┐   ┌───┐   ┌───┐   ┌──
       └───┘   └───┘   └───┘   └───┘
       ↑       ↑       ↑       ↑
MOSI ──X═══════X═══════X═══════X═════
       Sample  Sample  Sample  Sample
       (1st)   (1st)   (1st)   (1st)
```

**Mode 1 (CPOL=0, CPHA=1):**

```
SCK  ──┐   ┌───┐   ┌───┐   ┌───┐   ┌──
       └───┘   └───┘   └───┘   └───┘
           ↑       ↑       ↑       ↑
MOSI ──────X═══════X═══════X═══════X──
           Sample  Sample  Sample  Sample
           (2nd)   (2nd)   (2nd)   (2nd)
```

**Mode 2 (CPOL=1, CPHA=0):**

```
SCK  ───┐   ┌───┐   ┌───┐   ┌───┐   ┌
        └───┘   └───┘   └───┘   └───┘
        ↓       ↓       ↓       ↓
MOSI ───X═══════X═══════X═══════X════
        Sample  Sample  Sample  Sample
        (1st)   (1st)   (1st)   (1st)
```

**Mode 3 (CPOL=1, CPHA=1):**

```
SCK  ───┐   ┌───┐   ┌───┐   ┌───┐   ┌
        └───┘   └───┘   └───┘   └───┘
            ↓       ↓       ↓       ↓
MOSI ───────X═══════X═══════X═══════X
            Sample  Sample  Sample  Sample
            (2nd)   (2nd)   (2nd)   (2nd)
```

**Most commonly used: SPI_MODE_0 and SPI_MODE_3**

### 8.4.4 Additional Mode Flags

```c
/* Additional flags that can be OR'd with mode */
#define SPI_CS_HIGH     0x04    /* CS active high (not low) */
#define SPI_LSB_FIRST   0x08    /* LSB first (not MSB) */
#define SPI_3WIRE       0x10    /* 3-wire mode (MOSI=MISO) */
#define SPI_LOOP        0x20    /* Loopback mode */
#define SPI_NO_CS       0x40    /* No chip select */
#define SPI_READY       0x80    /* Slave pulls low to pause */
```

**Example usage:**

```c
spi->mode = SPI_MODE_0 | SPI_CS_HIGH | SPI_LSB_FIRST;
```

## 8.5 SPI Driver Structure - struct spi_driver

### 8.5.1 The spi_driver Structure

**Definition:**

```c
struct spi_driver {
    const struct spi_device_id *id_table;

    int (*probe)(struct spi_device *spi);
    int (*remove)(struct spi_device *spi);
    void (*shutdown)(struct spi_device *spi);

    struct device_driver driver;
};
```

**Field descriptions:**

- `id_table`: Array of device IDs this driver supports
- `probe`: Called when device is detected/matched
- `remove`: Called when device is removed
- `shutdown`: Called during system shutdown
- `driver`: Generic driver structure (contains OF match table)

### 8.5.2 Complete Driver Example

```c
#include <linux/module.h>
#include <linux/spi/spi.h>
#include <linux/of.h>

/* Device ID table */
static const struct spi_device_id my_spi_id[] = {
    { "my-spi-device", 0 },
    { "my-spi-sensor", 1 },
    { }  /* Sentinel */
};
MODULE_DEVICE_TABLE(spi, my_spi_id);

/* OF match table (Device Tree) */
static const struct of_device_id my_spi_of_match[] = {
    { .compatible = "vendor,my-spi-device", },
    { .compatible = "vendor,my-spi-sensor", },
    { }  /* Sentinel */
};
MODULE_DEVICE_TABLE(of, my_spi_of_match);

/* Probe function */
static int my_spi_probe(struct spi_device *spi)
{
    dev_info(&spi->dev, "Device probed: %s\n", spi->modalias);
    dev_info(&spi->dev, "Max speed: %u Hz\n", spi->max_speed_hz);
    dev_info(&spi->dev, "Chip select: %u\n", spi->chip_select);
    dev_info(&spi->dev, "Mode: 0x%04x\n", spi->mode);

    /* Device initialization goes here */

    return 0;
}

/* Remove function */
static int my_spi_remove(struct spi_device *spi)
{
    dev_info(&spi->dev, "Device removed\n");

    /* Cleanup goes here */

    return 0;
}

/* SPI driver structure */
static struct spi_driver my_spi_driver = {
    .driver = {
        .name = "my-spi-driver",
        .of_match_table = my_spi_of_match,
    },
    .probe = my_spi_probe,
    .remove = my_spi_remove,
    .id_table = my_spi_id,
};

/* Register driver */
module_spi_driver(my_spi_driver);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Your Name");
MODULE_DESCRIPTION("Example SPI Driver");
```

### 8.5.3 Driver Registration

**Old way (manual):**

```c
static int __init my_spi_init(void)
{
    return spi_register_driver(&my_spi_driver);
}

static void __exit my_spi_exit(void)
{
    spi_unregister_driver(&my_spi_driver);
}

module_init(my_spi_init);
module_exit(my_spi_exit);
```

**New way (recommended):**

```c
module_spi_driver(my_spi_driver);
```

The `module_spi_driver()` macro automatically generates init/exit!

## 8.6 The Probe Function

### 8.6.1 Probe Function Responsibilities

**Prototype:**

```c
static int my_probe(struct spi_device *spi);
```

**What the probe function should do:**

```c
static int my_probe(struct spi_device *spi)
{
    struct my_device_data *priv;
    int ret;

    /* 1. Configure SPI bus parameters */
    spi->mode = SPI_MODE_0;          /* Set SPI mode */
    spi->max_speed_hz = 20000000;    /* 20 MHz */
    spi->bits_per_word = 8;          /* 8-bit words */

    ret = spi_setup(spi);
    if (ret < 0) {
        dev_err(&spi->dev, "Failed to setup SPI: %d\n", ret);
        return ret;
    }

    /* 2. Allocate private data */
    priv = devm_kzalloc(&spi->dev, sizeof(*priv), GFP_KERNEL);
    if (!priv)
        return -ENOMEM;

    /* 3. Initialize private data */
    priv->spi = spi;
    mutex_init(&priv->lock);

    /* 4. Store private data */
    spi_set_drvdata(spi, priv);

    /* 5. Verify device communication (optional) */
    ret = my_device_test_communication(spi);
    if (ret < 0) {
        dev_err(&spi->dev, "Device communication test failed\n");
        return ret;
    }

    /* 6. Configure device */
    ret = my_device_configure(spi);
    if (ret < 0)
        return ret;

    /* 7. Register with kernel framework */
    ret = my_device_register(priv);
    if (ret < 0) {
        dev_err(&spi->dev, "Failed to register device\n");
        return ret;
    }

    dev_info(&spi->dev, "Device probed successfully\n");
    return 0;
}
```

### 8.6.2 Configuring SPI Bus - spi_setup()

**The `spi_setup()` function:**

```c
int spi_setup(struct spi_device *spi);
```

**What it does:**

- Applies the SPI mode, speed, bits_per_word settings
- Must be called before any data transfer
- Can be called multiple times to change settings

**Example:**

```c
/* Initial setup */
spi->mode = SPI_MODE_0 | SPI_CS_HIGH;
spi->max_speed_hz = 10000000;  /* 10 MHz */
spi->bits_per_word = 16;        /* 16-bit transfers */

ret = spi_setup(spi);
if (ret < 0) {
    dev_err(&spi->dev, "SPI setup failed\n");
    return ret;
}

/* Later, change to 8-bit mode */
spi->bits_per_word = 8;
ret = spi_setup(spi);
```

**Important difference from I2C:**

- I2C drivers CANNOT change bus parameters at runtime
- SPI drivers CAN change mode, speed, bits_per_word dynamically

### 8.6.3 Complete Probe Example

```c
struct my_adc {
    struct spi_device *spi;
    struct mutex lock;
    u16 reference_voltage;
};

static int my_adc_probe(struct spi_device *spi)
{
    struct my_adc *adc;
    int ret;
    u8 chip_id;

    dev_info(&spi->dev, "Probing ADC device\n");

    /* Check compatible mode */
    if ((spi->mode & SPI_MODE_3) != SPI_MODE_3) {
        dev_warn(&spi->dev, "Device requires SPI_MODE_3\n");
        spi->mode = SPI_MODE_3;
    }

    /* Set speed if not already set */
    if (!spi->max_speed_hz)
        spi->max_speed_hz = 1000000;  /* 1 MHz default */

    /* Default to 8-bit */
    spi->bits_per_word = 8;

    /* Apply settings */
    ret = spi_setup(spi);
    if (ret < 0) {
        dev_err(&spi->dev, "Failed to setup SPI\n");
        return ret;
    }

    /* Allocate driver data */
    adc = devm_kzalloc(&spi->dev, sizeof(*adc), GFP_KERNEL);
    if (!adc)
        return -ENOMEM;

    adc->spi = spi;
    mutex_init(&adc->lock);
    adc->reference_voltage = 3300;  /* 3.3V */

    spi_set_drvdata(spi, adc);

    /* Read chip ID to verify communication */
    chip_id = my_adc_read_register(spi, REG_CHIP_ID);
    if (chip_id != EXPECTED_CHIP_ID) {
        dev_err(&spi->dev, "Invalid chip ID: 0x%02x\n", chip_id);
        return -ENODEV;
    }

    dev_info(&spi->dev, "Chip ID verified: 0x%02x\n", chip_id);

    /* Register with IIO or other subsystem */
    /* ... */

    return 0;
}
```

## 8.7 Per-Device Data Management

### 8.7.1 Storing and Retrieving Data

**APIs:**

```c
/* Set SPI device data */
void spi_set_drvdata(struct spi_device *spi, void *data);

/* Get SPI device data */
void *spi_get_drvdata(const struct spi_device *spi);
```

**These are wrappers around:**

```c
dev_set_drvdata(&spi->dev, data);
dev_get_drvdata(&spi->dev);
```

### 8.7.2 Complete Example

```c
/* Device-specific data structure */
struct mc33880 {
    struct mutex lock;
    u8 bar;
    struct gpio_chip chip;
    struct spi_device *spi;
};

static int mc33880_probe(struct spi_device *spi)
{
    struct mc33880 *mc;
    int ret;

    /* Setup SPI */
    spi->mode = SPI_MODE_0;
    spi->bits_per_word = 8;
    ret = spi_setup(spi);
    if (ret < 0)
        return ret;

    /* Allocate private data */
    mc = devm_kzalloc(&spi->dev, sizeof(*mc), GFP_KERNEL);
    if (!mc)
        return -ENOMEM;

    /* Initialize */
    mutex_init(&mc->lock);
    mc->spi = spi;
    mc->chip.label = "mc33880";
    mc->chip.set = mc33880_set;
    /* ... more GPIO chip setup ... */

    /* Store private data */
    spi_set_drvdata(spi, mc);

    /* Register GPIO chip */
    return gpiochip_add(&mc->chip);
}

static int mc33880_remove(struct spi_device *spi)
{
    struct mc33880 *mc;

    /* Retrieve private data */
    mc = spi_get_drvdata(spi);
    if (!mc)
        return -ENODEV;

    /* Unregister */
    gpiochip_remove(&mc->chip);

    /* Cleanup */
    mutex_destroy(&mc->lock);

    return 0;
}
```

## 8.8 The Remove Function

### 8.8.1 Remove Function Structure

**Prototype:**

```c
static int my_remove(struct spi_device *spi);
```

**Example:**

```c
static int my_remove(struct spi_device *spi)
{
    struct my_device *dev = spi_get_drvdata(spi);

    /* 1. Unregister from kernel framework */
    my_device_unregister(dev);

    /* 2. Free IRQ if allocated */
    if (dev->irq_allocated)
        devm_free_irq(&spi->dev, spi->irq, dev);

    /* 3. Destroy locks */
    mutex_destroy(&dev->lock);

    /* 4. Free buffers (if not using devm_*) */
    /* kfree() not needed with devm_kzalloc() */

    dev_info(&spi->dev, "Device removed\n");

    return 0;
}
```

**Important:** Remove must undo everything done in probe!

## 8.10 Complete Driver Template

```c
#include <linux/module.h>
#include <linux/spi/spi.h>
#include <linux/of.h>

/* Private data structure */
struct my_device {
    struct spi_device *spi;
    struct mutex lock;
    /* Add your fields */
};

/* Device ID table */
static const struct spi_device_id my_id[] = {
    { "my-device", 0 },
    { }
};
MODULE_DEVICE_TABLE(spi, my_id);

/* OF match table */
static const struct of_device_id my_of_match[] = {
    { .compatible = "vendor,my-device", },
    { }
};
MODULE_DEVICE_TABLE(of, my_of_match);

/* Probe function */
static int my_probe(struct spi_device *spi)
{
    struct my_device *dev;
    int ret;

    /* Configure SPI */
    spi->mode = SPI_MODE_0;
    spi->max_speed_hz = 10000000;
    spi->bits_per_word = 8;

    ret = spi_setup(spi);
    if (ret < 0)
        return ret;

    /* Allocate private data */
    dev = devm_kzalloc(&spi->dev, sizeof(*dev), GFP_KERNEL);
    if (!dev)
        return -ENOMEM;

    /* Initialize */
    dev->spi = spi;
    mutex_init(&dev->lock);

    /* Store private data */
    spi_set_drvdata(spi, dev);

    /* Device-specific initialization */
    /* ... */

    dev_info(&spi->dev, "Probe successful\n");
    return 0;
}

/* Remove function */
static int my_remove(struct spi_device *spi)
{
    struct my_device *dev = spi_get_drvdata(spi);

    /* Cleanup */
    mutex_destroy(&dev->lock);

    dev_info(&spi->dev, "Device removed\n");
    return 0;
}

/* SPI driver structure */
static struct spi_driver my_driver = {
    .driver = {
        .name = "my-driver",
        .of_match_table = my_of_match,
    },
    .probe = my_probe,
    .remove = my_remove,
    .id_table = my_id,
};

module_spi_driver(my_driver);

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Your Name");
MODULE_DESCRIPTION("SPI Driver Template");
```

## Summary

In this part, we covered:

**Key Concepts:**

1. **SPI Protocol**
    - Four-wire bus (MOSI, MISO, SCK, CS)
    - Master-slave architecture
    - Full-duplex communication
    - Speeds up to 80+ MHz
2. **Linux SPI Subsystem**
    - SPI Core (abstraction layer)
    - SPI Controller (master driver)
    - SPI Device (client driver)
3. **Data Structures**
    - `struct spi_device`: Device instance
    - `struct spi_driver`: Driver code
    - `struct spi_device_id`: Device matching
4. **SPI Modes**
    - CPOL and CPHA combinations
    - Four modes (0, 1, 2, 3)
    - Most common: MODE_0 and MODE_3
5. **Driver Functions**
    - `probe()`: Device initialization with `spi_setup()`
    - `remove()`: Device cleanup
    - Per-device data management
6. **Registration**
    - `module_spi_driver()` macro
    - MODULE_DEVICE_TABLE for matching
